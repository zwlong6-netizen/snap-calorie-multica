## 三、各核心模块详细验收记录

### 1. AI 图像识别与兜底机制验收 (PRD 核心)
- **典型食物识别**：输入牛排样本 (`ribeye_steak.png`)，AI 模块稳定返回名称「香煎西冷牛排」、标量 200g、热量 488 kcal、蛋白质 46.2g、脂肪 32.0g、碳水 1.2g，置信度达 96%（满足 PRD ≥ 85% 要求）。
- **多食物识别矩阵**：对沙拉（香煎鸡胸肉沙拉）、全麦吐司、水煮蛋、红富士苹果、香煎三文鱼排等均实现准确映射与营养素换算。
- **离线与未知图片兜底**：输入随机噪点/未定义图片 (`random_noise_blurry_xyz.bmp`)，系统触发高保真兜底通道，返回符合规范的标准结构体，并附带 3 项备选食物候选卡片，保证端侧绝不崩溃。
- **模糊搜索容错通道**：支持中文名称、分类、英文别名（如输入 "americano" 检索到 "冰美式咖啡"）多模式检索，空检索词提供预设高频食物库。

### 2. 核心业务逻辑与动态差额计算联动 (Store & Dashboard)
- **基线数据核验**：用户每日目标卡路里为 2,000 kcal，初始状态已摄入 1,043 kcal，剩余可吃 957 kcal，达成度 52%，状态显示正常。
- **动态联动计算**：
  - 新增一条加餐苹果（200g, 104 kcal）后，总摄入立即动态增至 1,147 kcal，剩余热量减至 853 kcal。
  - 通过微调将克重调整为 300g (156 kcal) 时，总摄入与剩余卡路里毫秒级重算为 1,199 kcal 与 801 kcal。
  - 删除记录后，看板能量数值无缝回退基线。
- **摄入超标临界告警 (isOverLimit)**：当单日摄入超过 2,000 kcal 目标时，系统正确标记 `isOverLimit: true`，剩余热量变为负数，UI 层激活黄色/红橙告警样式与「⚠️ 已超出日摄入上限」提示。
- **动态 TDEE 目标调整**：支持动态调整用户每日目标卡路里及三大营养素目标（如修改为 2,500 kcal），仪表盘进度百分比自适应联动。

### 3. 前端 UI 界面与交互体验规范验收 (UI/UX 规范)
- **设计规范色一致性**：核验 CSS 变量与设计色彩系统，主品牌健康绿 (`#10B981`)、蛋白质蓝 (`#3B82F6`)、脂肪橙 (`#F59E0B`)、碳水粉 (`#EC4899`) 均严格对齐 TASK-29 视觉规范。
- **拍照与雷达波扫描**：全屏取景弹窗中，四角定位辅助线与 `.laser-scanner` 动效正常加载，识别触发时扫描动效加速，体验真实。
- **半屏浮层 (Bottom Sheet) 交互闭环**：
  - 具备 0.5x、1.0x、1.5x、2.0x 快捷档位吸附。
  - 支持滑块/加减按钮步进微调（20g~600g），营养素实时重算。
  - 支持手动精确克重弹窗输入与食物项模糊搜索更正。
  - 点击「确认打卡入库」后 ≤ 3 步完成主流程闭环。

### 4. 边界异常与系统健壮性 (Robustness)
- 404 API 路由与不存在记录的更新/删除请求均得到严格的状态码保护（返回 HTTP 404 与友好 JSON 报错）。
- 极值克重计算（0g、5000g）计算健全，无 NaN 或除零异常。
- 允许用户录入未在预设库中的自定义食物，系统自动根据预设模型推断基础宏量营养素并入库。
